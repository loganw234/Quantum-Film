## 1. How the crystal field is laid at coating time

### The data structure: counts and thresholds per cell, with no positions or sizes

A coated sheet (the "film stock") is a pair `(K, thr)` over the **flattened** pixel cells:

- **`K`**: int32 array of shape `(n_cells,)`. It holds the number of crystals in each cell (emulsion.py:141, 208).
- **`thr`**: uint16 array of shape `(n_cells, kmax)`. Each row holds that cell's crystal sensitivity thresholds, sorted ascending. Slots past the cell's own `K` are padded with 65535 (emulsion.py:155-163, 202-208). **(probe)** confirmed: rows are sorted, the padding is 65535, and the dtypes are int32 and uint16.

There are **no positions.** Each cell is "an independent column of emulsion" (emulsion.py:46-51), and "the field is white below the pixel" (processes.py:202-205).

There are **no sizes** either. Every crystal of a given process or stock has the same projected area, `grain_um2`: "the particle area is CONSTANT per process ... real emulsions carry size distributions" (processes.py:197-201). The thresholds do not depend on size, so there is no size-to-speed coupling. The references do cite fewer, larger grains as faster (docs/references.md:545-548).

In effect, a crystal is only a sensitivity rank inside its cell.

The docstring summarises the model (emulsion.py:9-17): "Each pixel-cell holds K crystals, K ~ Poisson(lambda_K) ... the cell's K thresholds are the order statistics of K uniforms, generated by the exponential-spacings construction and quantised to 16 bits."

### The distributions used

- **Count:** `K ~ Poisson(lam_K)`, drawn independently per cell (emulsion.py:141). The rate is `lam_K = ceiling * A / (kappa * a)`, where A is pitch squared and a is `grain_um2` (emulsion.py:183, 223).
- **Thresholds:** the order statistics of K independent Uniform(0,1) draws, built from exponential spacings (emulsion.py:133-163):

```python
E = rng.standard_exponential((n_cells, kmax + 1), dtype=np.float32)
C = np.cumsum(E, axis=1, dtype=np.float64)
denom = np.take_along_axis(C, K[:, None].astype(np.intp), axis=1)   # the (K+1)th partial sum
C /= denom
thr = np.minimum(C[:, :kmax] * 65536.0, 65535.0).astype(np.uint16)
thr[np.arange(kmax)[None, :] >= K[:, None]] = np.uint16(65535)       # padding
```

- **No crystal size distribution** exists anywhere in the package (processes.py:197-201).

### What "Nutting both ways" means in the code

Nutting's opaque-disc law is D = κ·N·a/A, with κ = log10(e) = 0.4342944819032518 (`KAPPA`, processes.py:60-70). The code uses it in both directions:

1. **Density to count, at coating.** `lam_K` is the mean crystal count per cell at which full development reaches the ceiling density (emulsion.py:183, 223).
2. **Count to density, at readout.** The developed density is `d = (KAPPA * a / A) * n` (processes.py:287; films.py:691; colour.py:362).

Because the same relation runs both ways, the mean is preserved "to the digit whatever kappa's value" (processes.py:66-69). The fluctuation is then Saunders' law, σ_D = sqrt(κ·a·D/A), with no free dial (granularity.py:3-14; PLAN.md:57-63; README.md:56-58).

The **ceiling** differs by path:

- prints: `pr["dmax"] * dmax_mul` (processes.py:269)
- camera stocks: `st["dmax"]` (films.py:689)
- colour layers: the layer's `span` (colour.py:359-360)

### How the seed enters

**Where it comes in.** Three public entry points take a `seed=`:

- `processes.process_print`, default 0 (processes.py:179)
- `films.negative`, default 0 (films.py:597)
- `colour.negative` and `colour.positive`, default 0 (colour.py:379, 469). Colour layer i is coated with `seed + i` (colour.py:361).

**The scheme.** `np.random.SeedSequence(seed).spawn(n_bands)` (emulsion.py:129-130), with `n_bands = ceil(n_cells / 2**23)` (emulsion.py:190, 226). Each band then gets `np.random.default_rng(child)` (emulsion.py:194, 229), which is a numpy `Generator` over **PCG64** **(probe)**.

The draw order within a band depends on the regime:

- exact path: `poisson(lam_K, n_band)` first, then `standard_exponential((n_band, kmax+1), float32)` (emulsion.py:141, 145)
- aggregate path: `poisson` first, then `random` (emulsion.py:239-240)

**What is not used.** There is no legacy `RandomState`, no global `np.random.seed`, and no Python `random` module. A grep finds only `default_rng` and `SeedSequence`, at emulsion.py:130, 194, 229 and films.py:541-542.

The batch lottery for the 1890 plates uses its own entropy pool, `SeedSequence([0x1890, int(batch)])` (films.py:541-542).

**Seed format.** Any non-negative int works end to end, including a 256-bit int **(probe)**. A negative seed raises `ValueError` **(probe)**.

**What the stream depends on:**

- **Array shape: yes.** The band count depends on `n_cells`. Inside a band, every threshold depends on the band's length and its realised `kmax`, because all the band's Poisson draws are taken before its exponentials (emulsion.py:141-145). The code says so itself: "the sheet is a function of (seed, shape) alone" (emulsion.py:218-220), and "draw order is a function of shape alone, never of the data" (emulsion.py:70-72). **(probe)**: coating 9,216 cells and then 10,000 cells with the same seed gives an identical `K` prefix, but **0 of 9,216** threshold rows match. Only the flat cell count matters, not the 2-D layout, because the input is `p.reshape(-1)` (emulsion.py:224) — **INFERRED** from the code. Full bands of 2**23 cells should be stable across sizes; only the last partial band changes (**INFERRED**, not probed because of memory).
- **`lam_K`: yes.** It depends on the ceiling, pitch and `grain_um2`. For prints the ceiling includes `dmax_mul`, which is a print-time dial (processes.py:269). **(probe)**: `dmax_mul=1.1` coats a different sheet for the same seed; `contrast=1.5` does not.
- **The image data: no.** The choice between regimes uses only `lam_K` (emulsion.py:230).
- **Thread count: no.** Nothing in the package uses threads, and numpy's `Generator` is single-threaded (**INFERRED**).
- **Call order: no.** Every call builds a fresh `SeedSequence` and `Generator`, and there is no module-level RNG state (emulsion.py:129-130, 194, 229). **(probe)**: spawned child 0 is identical whether you spawn 1 or 5 children.

## 2. How exposure thins the field and development amplifies it

### Thinning: exposure sets a developable fraction p

- **Prints:** `p = (1 - e^-dose)^(toe*contrast)` (processes.py:270-271). The docstring calls this the curve "read as the per-crystal probability it has always statistically been" (emulsion.py:19-21).
- **Camera stocks:** `p = D(log10 H) / dmax`, fog included. That is equivalent to `p = p_fog + (1 - p_fog)·u`, so "FOG COUNTS CRYSTALS" (films.py:16-20, 674).
- **Colour layers:** `p = d / span` (colour.py:358).

A crystal develops if and only if its stored threshold is at or below p, compared at 16 bits (emulsion.py:166-174):

```python
pq = np.clip(np.floor(np.asarray(p, np.float64).reshape(-1) * 65536.0), 0.0, 65535.0).astype(np.uint16)
n = (thr <= pq[:, None]).sum(axis=1, dtype=np.int32)
return np.minimum(n, K.astype(np.int32))
```

Development "draws nothing" (emulsion.py:169-170). That gives four properties:

- more light on the same sheet can only develop more crystals
- a saturating exposure prints the sheet itself
- at any single exposure the count is Binomial(K, p), and with K Poisson that is Poisson(lam·p) — the thinning theorem
- the increments between two exposures have variance `Var(n2 - n1) = lam(p2 - p1)` (emulsion.py:23-35)

### Amplification: all or nothing, then optional scaling

One latent speck develops the whole crystal. This cites dossier B9/B12 (emulsion.py:23-24), backed by the Solberg patent, Tani, and Fayet 1985 (docs/references.md:545-562). Each developed crystal adds its full area: `d = κ·a/A · n` (films.py:691).

After development, two optional stages multiply the developed field, grain included:

- the intensifier's bath, ×1.656, for collodion only (films.py:557-569, 691)
- the plates' pouring field (films.py:670-671)

### The regime split, which matters for fixer

The exact threshold path runs only when `lam + 8*sqrt(lam) + 16 <= 192` (emulsion.py:230).

Otherwise the **aggregate** path runs. Each cell gets one Poisson count K and one uniform v, and the count is `n = clip(rint(K·q + sqrt(K·q·(1-q))·Φ⁻¹(v)), 0, K)` (emulsion.py:233-244), using Acklam's approximation for Φ⁻¹ (emulsion.py:91-126). In this regime:

- there are **no per-crystal thresholds**
- there is **no storable sheet**: `coat` refuses (emulsion.py:184-189)
- the increment law is declared out of scope (emulsion.py:58-62, 234-238)

Where the boundary falls **(probe)**:

| Stock or process | Exact path runs between | Notes |
|---|---|---|
| TRI-X | 1.24 µm (its floor) and 4.10 µm | lam ≈ 3,610 at 25 µm |
| Silver paper | up to ≈ 2.0 µm | |
| Gum | up to ≈ 16 µm | |
| Platinum, salt, vandyke | up to ≈ 0.1 µm | |
| **Every camera stock** | — | aggregate at 25 µm |

At TRI-X and 25 µm, the aggregate path is still pixelwise monotone (0 violations over 6 exposure steps). But its increments are about **6× under-dispersed**: Var(n2 - n1) = 85.7 against lam·Δp = 543.9 **(probe)**. That is exactly the "watched failure" the thresholds were introduced to fix, in the exact regime only (test_the_grain_is_a_count.py:253-261).

### The full black-and-white chain: subject to negative to print

atlas-film has no single chain function. The darkroom wires `develop(film=)` (PLAN.md:171-173). With the public functions, a caller writes:

```python
from atlas_film import films, processes, granularity
E  = films.normal_exposure(scene, "trix")            # films.py:695-708; meters to normal_highlight, films.py:459-473
D  = films.negative(scene, E, "trix", pitch_um=2.0, seed=S)          # films.py:597-692 -> float32 density, fog and grain
T  = films.transmit(D)                               # films.py:711-713, printing light 10^-D
pr = processes.process_print(np.repeat(T[..., None], 3, -1), E_print, "silver",
                             grain=True, pitch_um=2.0 * mag, seed=S2)  # processes.py:178-293 -> RGB reflectance
```

**Inside `films.negative`, in order:**

1. stock validation (films.py:629) and the intensify factor (films.py:630)
2. spectral projection times E, clamped at zero (films.py:631, 476-484)
3. the traced MTF, applied as an exact transfer in frequency space — only if `pitch_um` is given, the stock has an MTF, and the input is 2-D (films.py:632-637)
4. halation, only if asked (films.py:638-661)
5. the batch speed shift and pouring field (films.py:662-665)
6. reciprocity (films.py:666-667)
7. `D = characteristic(log10 dose, ci)` (films.py:668-669)
8. with `grain=False`, return `D` (films.py:672-673)
9. otherwise compute `p = D/dmax`, then develop against `sheet=` or call `emulsion.expose` (films.py:674-690)
10. return `f · κa/A · n` as float32 (films.py:691-692)

**Inside `process_print`:**

1. luma-weighted dose × E × speed (processes.py:218-219)
2. clamp at zero (processes.py:228)
3. response curve (processes.py:251)
4. grain block (processes.py:252-287)
5. per-channel absorption, returning `base * 10^(-d·absorb)` as float32 (processes.py:288-293)

The enlarger's exposure `E_print` and the magnification are the caller's decisions (PLAN.md:126-131). **INFERRED:** in practice the darkroom meters them.

The paper's grain is a second, independent sheet with its own seed at the print's own pitch: "Two sheets, two grains, compounding" (PLAN.md:126-132).

The instruments that read results back are `granularity.density_field`, `rms_granularity` and `selwyn_coefficient` (granularity.py:38-79), plus the `sensitometry` readers (sensitometry.py:66-102).

## 3. How a stock is declared, and how refusal works

### The fields a stock must supply

`FILMS` is a plain module-level dict of dicts (films.py:110-278). There is **no registration API and no class to subclass.** Tests add stocks with `monkeypatch.setitem(films.FILMS, ...)` (test_the_negative_is_a_sheet.py:34-42).

**Required**, checked by `_stock` (films.py:353-374):

- **A response curve.** Either the family `fog, dmax, gamma, ht, wt, ws` (`_CURVE_KEYS`, films.py:280), or a sampled table `curve=(xs, ds)` (for example films.py:188-196). Table stocks still need `fog` and `dmax`, which are used at films.py:450, 469, 674 and 689, but `_stock` does not check for them. **INFERRED:** a missing one surfaces as a bare `KeyError`.
- **`sens`**, a 3-weight spectral projection. Every shelf entry must sum to 1 (test_the_eye_and_the_clock.py:67-71).
- **`grain_um2`**, whenever `grain=True`, which is the default for camera stocks. This one is **not** checked: a missing value raises a bare `KeyError('grain_um2')` **(probe)**. By contrast, `process_print` refuses by name (processes.py:213-217), and so does colour (colour.py:352-357).

**Optional, one table per organ:**

- `CONTRAST[name]` enables `ci=` (films.py:299-326)
- `RECIPROCITY[name]` enables `t=` (films.py:340-350)
- `mtf.MTF_BW[name]` (mtf.py:46-55); a stock without one stays pixel-sharp by declaration, silently (mtf.py:34-37)
- `halation.SUPPORTS` or `REFUSALS` (halation.py:160-243)
- the batch lottery is hard-coded to the two plates (films.py:534)
- the intensifier works only for table stocks (films.py:576)

### How refusal by name works

Each gap raises a `ValueError` whose message states why. Refusal points:

| Missing curve keys: "a curve invented for a named real film would be a lie wearing a datasheet's name" | films.py:359-367 |
| Missing `sens` | films.py:368-373 |
| `ci=` on a stock without a contrast table; separate reasons for collodion (mechanism), the plates ("the capacity question") and the rest | films.py:381-399 |

| Reciprocity: no table, or outside the span ("silence is not zero") | films.py:494-505 |

| Print particle area missing | processes.py:213-217 |

The charter, in the README: "Where a datasheet is silent the model raises with the reason and the dossier entry rather than filling the gap with something plausible — because a number invented for a named real film is a lie wearing a datasheet's name" (README.md:13-16).

### Admitting a new, non-historic stock honestly

The objection in the charter is specifically to invented numbers carried under a **real product's name**. The code has several precedents for numbers that are honest without being sourced.

**The halation strength: "the operator's number, named as one".** This is exactly the precedent fixer needs:

- The constant itself is refused: `SCATTER = None` (halation.py:245-256).
- The caller passes `halation=` as a fraction in [0, 1] of a **sourced ceiling** (halation.py:402-428), checked in `for_stock` (halation.py:431-453).
- The negative's docstring tells the caller the strength is theirs (films.py:621-627, 643-648), and so does README.md:84-88: "The strength has never been published ... so it is the operator's number, named as one, measured against a sourced ceiling."

**Other precedents:**

- bracketed constants that are "wearing their flag": the plates' grain (films.py:142-147), their glass thickness (halation.py:172-187), collodion's axis (films.py:171-177)
- declared projections that are not fits (films.py:95-106)
- granularity-equivalent noise constants (colour.py:22-29; films.py:178-183)
- class values flagged as such (colour.py:283-301)
- axes anchored by construction, with the tests labelled "wiring" rather than discovery (films.py:218-229, 239-249; test_four_more_sheets.py:33-40)
- fictional stocks injected only in tests, under obviously fake names: "teststock" (test_the_negative_is_a_sheet.py:34-42) and "fakecolour" (test_colour_is_three_sheets.py:20-55)

**An honest route for fixer (INFERRED recommendation):**

1. Keep the stock off the shelf and inject it at runtime inside fixer, as the tests do.
2. Give it its own name, not a product's.
3. Reuse a sourced stock's curve and `grain_um2` by reference (for example TRI-X), so the count law and density scale stay sourced. Only the source of the crystal field then changes.
4. Name any new quantum parameter as the operator's, with a bound, the way halation does.

A caution: adding the stock to `FILMS` in atlas-film's own source would break two tests that iterate the whole shelf. test_every_stock_declares_its_eye requires `sens` (test_the_eye_and_the_clock.py:67-71). The halation test requires a `REFUSALS` reason for every stock that does not halate (test_the_light_that_comes_back.py:249-267).

## 5. Determinism

### What the code claims

- "same seed, same geometry - same crystals, whatever is later printed on them" (emulsion.py:14-17)
- the stored stock is "bit-identical to the throwaway path with the same seed. A stored stock also outlives numpy: the RNG only runs at coating, and the saved crystals are just integers" (emulsion.py:37-44)
- a fixed band size, "so the draw sequence never depends on the data" (emulsion.py:56-57, 70-72, 218-220)
- a coarse-pitch MTF or halation is "a true no-op, bit-identical" (mtf.py:92-98; halation.py:460-466)
- the LAD printer-light solve converges "deterministically" (colour.py:443-448)
- the batch lottery is "deterministic in the batch number" (films.py:531-533)
- PLAN's non-goal: "the negative's determinism story is the camera's" (PLAN.md:693-694)

### What actually holds

**(probe):** the same seed, `n_cells` and `lam` give identical `(K, thr)`. `sheet=` output equals seeded output. Spawned children do not depend on the band count.

"The seed alone" does **not** cover four things:

1. **Cell count.** One extra pixel reshuffles every threshold **(probe)**.
2. **`lam_K`, including `dmax_mul`** **(probe)**.
3. **The numpy version.** numpy only promises stable streams for its bit generators (PCG64 and SeedSequence), not for `Generator` distributions such as `poisson` or `standard_exponential` (**INFERRED**, from numpy's stream-compatibility policy, NEP 19). The integers of a stored sheet survive a numpy upgrade; a reseeded coating may not.
4. **The platform.** See the floating-point hazards below.

### Floating-point hazards

**Coating.** The arithmetic after sampling is exact under IEEE 754:

- a sequential float64 `cumsum` (emulsion.py:146)
- one correctly rounded division (emulsion.py:154)
- scaling by 65536, a power of two, then truncation to uint16 (emulsion.py:155)
- `lam_K` built from Python floats (emulsion.py:183)

The remaining risk is **inside numpy's samplers** (**INFERRED**, from numpy's `distributions.c`, not read here):

- Poisson at lam ≥ 10 uses PTRS rejection with `log()` and `loggam`. That covers most exact-regime pitches and all aggregate ones.
- Poisson at lam < 10 uses the multiplication method, with one `exp(-lam)`. That happens near the floor: TRI-X at 1.24 µm gives lam ≈ 8.9, and silver at 0.5 µm gives ≈ 6.2.
- The float32 exponential is a ziggurat whose rare tail steps call `log`.

A last-bit difference in libm could flip one accept or reject decision, which would desynchronise the whole remaining stream. The probability is tiny but not zero.

**Exposure.** The developable fraction p passes through:

- `np.exp` and `**` (processes.py:251, 270-271)
- `np.log10` and `np.logaddexp` (films.py:453-456, 668)
- `np.interp` (films.py:450)
- `@` for the RGB projection (films.py:483; colour.py:323); **INFERRED** to dispatch to BLAS gemv
- the FFTs in the MTF and halation organs (mtf.py:101-106; halation.py:479-486)
- in the aggregate path, `np.log`/`np.sqrt` inside Φ⁻¹ and `np.rint` (emulsion.py:122, 243-244)

The MTF FFT **runs at every practical pitch** for the four Kodak B&W stocks. It is a no-op only above 83-196 µm **(probe)**.

**INFERRED:** numpy's SIMD dispatch (AVX2 versus AVX512/SVML), the BLAS kernel, and pocketfft differences between numpy 1.x and 2.x can each change the last bits of p. That changes a count only when `p*65536` falls within a few ulp of an integer (exact path) or on a .5 rounding boundary (aggregate path). Rare, but not provably never.

Outputs are cast to float32 (films.py:691-692; processes.py:293). The only reduction in the image path, `develop_on`, is an integer sum and therefore exact (emulsion.py:173). Pairwise float reductions appear only in the readers (granularity.py:62, 68).

For context: CI (Ubuntu, Python 3.11, latest numpy) and this machine (Windows, Python 3.12, numpy 2.2.6, AVX2) are different configurations.

### Hashing

atlas-film hashes nothing: no `hashlib` or digest calls in code or tests. `.gitattributes:1-3` says the figure sidecars "are compared by digest", but that comparing tool is not in this repo. **INFERRED:** it is the darkroom's `tools/readme_figures.py` or `film_golden.py`.

## 7. The minimal change for an external crystal field, and installability

### Options, from no change upward

**Option 0: a quantum seed. No change to atlas-film.** Pass `seed=int.from_bytes(quantum_bits, "big")`. A 256-bit int works end to end through `films.negative` **(probe)**. Colour's `seed + i` is plain int arithmetic, so it should work too (**INFERRED**). The quantum luck is then fixed once, but the field is still expanded classically by PCG64 through numpy's Poisson and exponential samplers.

**Option 1: `sheet=`. No change to atlas-film.** An existing public injection point on `films.negative` (films.py:598, 680-687) and `process_print` (processes.py:179, 272-283): "the seed is unused because the stock IS the identity" (processes.py:274-275). fixer builds `(K, thr)` from its quantum process and passes it:

```python
D = films.negative(scene, E, "trix", pitch_um=2.0, sheet=(K, thr))
```

The contract, read from the code:

- `K` is an integer array of shape `(n_cells,)`, with `K.shape[0] == image.size` (films.py:681-686).
- `thr` is uint16 of shape `(n_cells, kmax)`. Each row holds that cell's K thresholds, and the rest is 65535. `develop_on` counts `thr <= floor(65536p)` and clips to K; it does not need the rows sorted (emulsion.py:166-174). `coat` does sort them.
- To keep the density scale and Saunders' law right, the mean of K must equal `dmax * pitch**2 / (KAPPA * grain_um2)` (emulsion.py:183 together with films.py:691). **Nothing checks this.**
- `sheet=` **skips the honesty floor and the aggregate-regime refusal** **(probe)**.

**Option 2: colour. About six lines added upstream.** `colour._develop_layers` always calls `emulsion.expose(..., seed + i)` (colour.py:358-362). Add a `sheets=None` argument (three `(K, thr)` pairs) to `colour.negative`, `colour.positive` and `_develop_layers`, mirroring `films.negative`'s `sheet=` branch.

**Option 3: a first-class seam. A small upstream change.** `_coat_band(rng, n_cells, lam_k)` (emulsion.py:133-163) is the single coating seam that both `coat` (emulsion.py:194) and `expose`'s exact path (emulsion.py:231) call. Expose it as an optional `coater=` argument on `coat` and `expose`, threaded through the three entry points, or as a documented module hook.

fixer *could* monkeypatch `atlas_film.emulsion._coat_band` today with no upstream change. That would reach B&W, prints and colour at once. It is a private name, although the tests deliberately reach into private helpers (pyproject.toml:32-34).

The aggregate path does not call `_coat_band` (emulsion.py:233-244). Practical pitches (≳5 µm for TRI-X) need either a second hook for a `(K, v)` pair per cell, or rendering at a pitch that resolves crystals.

**Budget arithmetic (INFERRED):** at 2 µm, TRI-X coats about 23 crystals per cell. A 4096² sheet therefore holds about 3.9×10⁸ crystals, and at 16 bits each that is about 6.2 Gbit of threshold entropy. That argues for a quantum seed (Option 0), a small quantum tile, or quantum-sourced *parameters*, rather than measuring every threshold directly.

## Anything surprising

1. **Zero exposure still develops some crystals.** Because thresholds are compared at 16 bits, a crystal develops with probability (floor(65536p) + 1)/65536, not p. At exactly zero exposure, 1/65536 of crystals develop: 94 of 262,144 silver cells at 1 µm got a speck **(probe)**. It is a tiny, systematic upward bias that no test examines.
2. **At render pitch, the "sheet" is really the old coupling.** Every stock at 25 µm runs the aggregate path. It has no thresholds, cannot be stored, and its increments are 6× under-dispersed **(probe)**. The object-like guarantees (sheet before light, monotone increments, storable stock) are tested only at 1-2 µm.
3. **The field depends on more than the seed.** It is a function of the seed, the total cell count, and `lam_K`. A print-time dial, `dmax_mul`, re-coats the sheet **(probe)**, which is at odds with "the crystal field is laid at coating time from the seed alone".
4. **Colour seeds collide across frames.** Layer i uses `seed + i` (colour.py:361), so frame s's green layer uses the same PCG64 stream as frame s+1's red layer (**INFERRED**). All entry points default to `seed=0`, so a caller who forgets the seed coats identical sheets every time.
5. **`sheet=` skips the physics checks.** It bypasses the honesty floor and the aggregate refusal, and never checks the mean of K. Separately, `films.negative` raises a bare `KeyError` for a missing `grain_um2`, breaking the refusal-by-name contract that `process_print` and colour both keep.
6. **The unsourced dmax values feed grain directly.** For vandyke, salt, albumen and gum, the crystal count per cell is derived from an unsourced dmax. For camera stocks it comes from the datasheet's *plotted* top, "NOT emulsion capability" (films.py:84-87).
7. **One plate has a negative fog floor.** hd22's curve floor is −0.0100 D (docs/curves.json:19), from the smooth shoulder cap (films.py:455-456). Its p is slightly negative at zero exposure and gets clipped.
8. **Housekeeping gaps.** PLAN.md has stale passages (listed in §6). The public evidence file, `docs/references.md`, is still uncommitted. `.gitignore:1-8` carries atlas-optical's glass-catalogue rules. The README says 0.5 µm is "finer than one crystal" (README.md:60-62), but 0.5 µm is exactly the floor for a 0.196 µm² particle (0.4996 µm), and the code refuses anything finer.
9. **Memory is the practical limit of the exact path.** Coating allocates float32 exponentials of shape `(band, kmax+1)`, about 0.9 GB per band (emulsion.py:145-154). The colour figure recorded a peak RSS of 19.9 GB (docs/colour.txt).
